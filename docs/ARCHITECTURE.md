# OmniSteam 系统架构设计白皮书 (Monorepo 架构)

## 1. 架构总览与设计准则

OmniSteam 采用 **“内核隐身注入 (Headless Core) + 独立管理面板 (Decoupled Manager)”** 的解耦架构：

- **Core (注入核心)**：追求**零 UI、极致轻量、零检测面、跨平台 ABI 稳定**。仅作为 Steam 进程内探针，专注 IPC 协议过滤与密钥提供。
- **Manager (管理终端)**：追求**易用性、功能丰富、独立生命周期**。提供跨平台 GUI/Web 界面，负责 Steam API 查询、Lua 脚本可视化生成与 WebDAV 云存档同步。
- **IPC / 通信契约**：两者通过**操作系统标准文件系统与内核级文件变更通知（inotify / ReadDirectoryChangesW / kqueue）**单向/双向解耦通信，无需在 Steam 进程内启动额外 Socket 或 HTTP 服务。

## 3. 核心子系统详细设计

### 3.1 Core (注入核心层)
1. **注入契约**：
   - Windows: `dwmapi.dll` / `xinput1_4.dll` 劫持并透明转发。
   - Linux / SteamOS: `LD_PRELOAD` 启动。
   - macOS: `DYLD_INSERT_LIBRARIES` 注入。
2. **Hook 范围**：
   - `ConfigStore::GetBinary`：拦截 Depot 解密 Key 与本地 Ticket 读取。
   - `CSteamClient::IPCProcessMessage`：拦截 Protobuf 格式的游戏与 Steam 通信。
   - `CKeyValues::LoadFromFile`：篡改 AppInfo 元数据。
3. **安全边界**：
   - 不开启任何监听端口，无 GUI 线程，不修改 Steam 可执行文件磁盘 Hash。

### 3.2 Manager (管理应用层)
1. **技术栈**：推荐 **Tauri 2.0 (Rust + Web前端)** 或 **Go/Wails**。
2. **游戏检索与元数据**：
   - 聚合 Steam 官方公开 API (`https://store.steampowered.com/api/appdetails?appids=...`) 与 SteamDB 格式数据。
   - 用户输入游戏名即可勾选主游戏及所有 DLC，一键自动写入 `.lua` 脚本。
3. **WebDAV / S3 云存档引擎**：
   - 自动检测各操作系统 Steam 存档标准路径（Windows: `AppData/Local`, `Saved Games`; Linux: `~/.local/share/Steam/steamapps/compatdata/<appid>/pfx`）。
   - 提供差异比对、压缩加密、增量上传与版本回退。
