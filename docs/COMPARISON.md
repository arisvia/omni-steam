> 定位声明: OmniSteam 是**客户端侧 (steamclient) Hook 方案**, 与游戏侧 API 包装方案(如 SmokeAPI)互补而非互斥。

## 2. 各家优势借鉴

### GreenLuma
- **优点**: 十余年生产验证的稳定性; 极简部署; 对老版本 Steam 兼容性记录完整。
- **启示**: 简单可靠 > 功能堆叠。OmniSteam 的 `dwmapi` 代理同样追求"零配置可工作"底线。

### OpenSteamTool
- **优点**: 协议级实现质量高 (proto 定义齐全); 签名库按版本分发思路成熟; 活跃维护。
- **已吸收**: 供体 SteamID 服务、上游特征锚点、`bFreeLicense=false` 等关键行为语义。
- **差异化**: OmniSteam 增加 Manager 三层仪表盘、WebDAV 存档、反作弊白名单、五级自愈寻址,
  并将签名采集全自动化(CI 锚点→派生→验证→回推), 不再依赖人工逆向节奏。

### SmokeAPI
- **优点**: 游戏侧包装天然规避客户端检测面; 单游戏粒度控制精细; 社区庞大。
- **启示**: 对**无法以客户端身份启动**的场景 (绿色版/独立启动器拉起) 是唯一解。
- **路线图**: 见 §4 增强项 G1 (游戏侧包装模式)。

### Goldberg Emu
- **优点**: 完全离线, 局域网联机模拟独一无二。
- **启示**: 离线场景兜底价值; 但替换式方案对在线功能(DLC 校验服务端化趋势)长期风险更高。

## 3. OmniSteam 已建立的护城河

1. **零维护函数寻址**: Linux/macOS 运行时符号表解析 + Windows 远程签名库自动拉取,
   Steam 客户端更新后无需任何人工介入即可恢复工作 (竞品普遍需要等待维护者发版)。
2. **安全纵深**: 反作弊白名单直通是硬性账号安全保障; Host/Origin 回环校验、路径操作
   白名单、Lua 沙箱、密码不回显等在同类中罕见。
3. **供应链可信**: depotkeys/Core 包 sha256 边车验证; 签名数据全部派生自 Valve 官方字节流。
4. **全生命周期管理**: 从发现→解锁→密钥匹配→库内可见→下载授权→成就→云存档备份的单链路闭环,
   外加 Decky 掌机插件与 Doctor 自检。
